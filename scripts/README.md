# Скриншоты сайтов

Отдельный ручной инструмент на Playwright + Chromium. Компоненты Astro и данные
проектов он не изменяет. Все команды ниже выполняются из корня проекта, в том числе
в PowerShell на Windows 11. Используйте Node.js 24, как в основном проекте.

## Установка

```sh
npm install
npx playwright install chromium
```

После обновления Playwright повторите установку браузера. Браузер запускается
автоматически в headless-режиме, открывать окно вручную не нужно.
Если PowerShell блокирует `npm.ps1`/`npx.ps1`, используйте `npm.cmd`/`npx.cmd`.

## Конфигурация

Редактируйте `scripts/screenshots.config.json`. Начальная запись `example` —
доступный тестовый сайт; замените её реальными проектами или добавьте новые записи.
Конфигурация независима от Markdown и ID проектов портфолио.

```json
{
  "viewports": {
    "desktop": { "width": 1440, "height": 900 },
    "mobile": { "width": 390, "height": 844 }
  },
  "projects": [
    {
      "id": "project-one",
      "urls": [
        { "name": "homepage", "url": "https://example.com" },
        { "name": "features", "url": "https://example.com/features" }
      ]
    }
  ]
}
```

`/features` в этом примере — условный путь: укажите существующую страницу своего
сайта. Поддерживаются HTTP и HTTPS, включая локальные сайты. Логин и пароль в URL
не допускаются. ID проектов уникальны, имена страниц уникальны внутри проекта.
Для `id` и `name` используйте строчные латинские буквы, цифры и одиночные дефисы
между ними, максимум 80 символов. Системные имена Windows (`con`, `nul` и т. п.)
запрещены. Неизвестные поля и параметры вызывают ошибку до запуска браузера.

Размеры меняются в `viewports.desktop` и `viewports.mobile`. Если `viewports` или
одно из устройств не указано, используются размеры из примера. Размеры PNG задаются
в пикселях без увеличения по DPR. Mobile использует Chromium с `isMobile`, touch
и мобильным User-Agent Pixel 5; это эмуляция мобильного устройства, а не Safari.

### Cookie-баннер

По умолчанию скрипт ничего не нажимает и не скрывает элементы сайта. Чтобы явно
нажать кнопку баннера, добавьте на уровень проекта:

```json
"cookieAction": { "selector": "button:has-text(\"Reject optional cookies\")" }
```

Укажите точный [Playwright selector](https://playwright.dev/docs/locators) своего
сайта. Действие — один обычный click после загрузки страницы, до прокрутки.
Если кнопка не найдена, неоднозначна или недоступна за 5 секунд, съёмка этого
устройства завершается ошибкой, прежние файлы сохраняются. Другие устройства и URL
продолжают обрабатываться. Действие выполняется отдельно для каждого устройства:
каждый контекст имеет чистые cookies и storage.

На уровне страницы можно задать другой `cookieAction` или `"cookieAction": null`,
чтобы отключить унаследованное действие проекта. Используйте эту настройку только
для cookie-баннеров. Авторизацию, CAPTCHA и ограничения доступа инструмент не
обходит. Если сайт возвращает экран входа или CAPTCHA с HTTP 200, такой экран
может попасть в снимок: содержимое нужно проверить визуально.

## Запуск

```sh
npm run screenshots
npm run screenshots -- --project project-one
npm run screenshots -- --project project-one --page homepage
npm run screenshots -- --project project-one --device desktop
npm run screenshots -- --project project-one --device mobile
npm run screenshots -- --help
```

`--page` требует `--project`; `--device` можно сочетать с обоими фильтрами.
Для отдельного списка сайтов: `npm run screenshots -- --config scripts/other.json`.
Относительный путь `--config` считается от текущей папки. Результаты всегда
сохраняются в `screenshots/` в корне этого проекта.

## Результаты и обновление

```text
screenshots/
  project-one/
    homepage/
      desktop.png
      desktop-full.png
      mobile.png
      mobile-full.png
```

`desktop.png` и `mobile.png` содержат верхнюю видимую область; `*-full.png` — всю
страницу. Повторите ту же команду, чтобы обновить нужные файлы. Каждый старый PNG
заменяется только после успешного захвата и записи нового; при ошибках старые
файлы не удаляются. Два снимка одного устройства обновляются независимо, поэтому
при частичной ошибке они могут относиться к разным запускам. Не запускайте съёмку
одних и тех же страниц одновременно.

Исходники PNG исключены из Git через `.gitignore` и не попадают в сборку Astro.
Когда решите добавить их в кейсы, вручную перенесите выбранные файлы в существующую
структуру `src/content/companies/<company>/projects/<project>/` (рядом с Markdown
отдельного проекта) или `src/content/companies/<company>/` (для компании целиком)
и добавьте ссылки в Markdown.

В терминале выводятся URL, созданные файлы, предупреждения загрузки, причины ошибок
и итоговое количество успешных/неудачных PNG. Ошибки конфигурации, браузера или
хотя бы одного снимка дают ненулевой exit code; предупреждения о ресурсах — нет.

## Ожидание контента

Скрипт ждёт DOMContentLoaded (до 30 секунд), затем load (ещё до 10 секунд),
прокручивает страницу шагами по 75% высоты окна с паузами 300 мс и возвращается
наверх. Прокрутка ограничена 30 секундами и 100 шагами, чтобы бесконечная лента не
блокировала обработку остальных сайтов. После прокрутки и возврата наверх он ждёт
изображения (до 8 секунд) и шрифты (до 5 секунд); проблемы выводятся как
предупреждения. На захват каждого PNG отводится до 30 секунд.

Используются `reducedMotion: reduce` и `animations: disabled` при съёмке.
Видео, canvas, динамические данные, бесконечные ленты, вложенные scroll-контейнеры
и нестандартные механизмы lazy-loading могут потребовать проверки результата.
Элементы интерфейса, sticky/fixed-блоки и баннеры автоматически не скрываются.
Полнота содержимого зависит от сайта; сетевые ошибки ресурсов видны в отчёте,
но не всегда мешают получить PNG.

Справка: [эмуляция устройств](https://playwright.dev/docs/emulation),
[снимки страниц](https://playwright.dev/docs/screenshots),
[установка браузеров](https://playwright.dev/docs/browsers).

## Проверка инструмента

```sh
node --test scripts/screenshots.test.mjs
```

Проверка использует локальный HTTP-сайт и Chromium: проверяет размеры PNG,
мобильную эмуляцию, lazy-loading, cookieAction, продолжение после HTTP-ошибки и
сохранность старых изображений. Временные результаты удаляются после проверки.
